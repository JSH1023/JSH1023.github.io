관점 1. 입력 검증

SQL 인젝션 및 XSS 관련 코드 변경 내용을 정리합니다.

1-2 | SQL 쿼리 매개변수 처리

DB 조회에 Prepared Statement를 적용합니다.

수정 전

$query = "SELECT * FROM users WHERE username = '$username' AND password = '$password'";

수정 후

$stmt = $conn->prepare("SELECT id, username, nickname, is_admin FROM users WHERE username = ? AND password = ?"); $stmt->bind_param("ss", $username, $password);

1-3 · 1-5 | 게시글·댓글·쪽지 출력 처리

출력 시 htmlspecialchars()를 사용하도록 변경합니다.

수정 전

<?php echo $post['title']; ?>

수정 후

<?php echo htmlspecialchars($post['title'], ENT_QUOTES, 'UTF-8'); ?>

1-4 | 오류 메시지의 사용자 입력 출력

오류 메시지에 포함되는 사용자 입력값을 htmlspecialchars()로 처리합니다.

수정 전

echo "<span style='color:red;'>이미 사용 중인 아이디입니다 ($username).</span>";

수정 후

$safe_username = htmlspecialchars($username, ENT_QUOTES, 'UTF-8'); echo "<span style='color:red;'>이미 사용 중인 아이디입니다 (" . $safe_username . ").</span>";

2-3 | 세션 쿠키 설정

세션 시작 전에 HttpOnly와 SameSite 옵션을 설정합니다.

수정 전

// 기존: 기본 설정으로 세션 시작 
session_start();

수정 후

// 변경: HttpOnly 및 SameSite 옵션을 설정한 뒤 세션 시작 
if (session_status() === PHP_SESSION_NONE) { 
session_set_cookie_params([ 
'lifetime' => 0,
'path' => '/', 
'domain' => '', 
'secure' => false, // HTTPS 환경 사용 시 true 
'httponly' => true, // JS를 이용한 쿠키 접근 차단 
'samesite' => 'Lax' ]); 
session_start(); 
}

2-4 | 로그인·로그아웃 시 세션 처리

로그인 직후 세션 ID를 재발급하고, 로그아웃 시 세션 배열 초기화·쿠키 만료·세션 파기를 수행하도록 변경합니다.

수정 전

// 기존: 단순히 session_destroy만 실행 // logout.php 
session_destroy(); 
header("Location: index.php");

수정 후

// 2-3 에서 수정한 login.php 파일을 한번 더 추가 수정
if (password_verify($password, $user['password'])) {
    // 세션 고정 공격(Session Fixation) 방지를 위해 세션 ID 재발급 
session_regenerate_id(true); 
$_SESSION['user_id'] = $user['id']; $_SESSION['username'] = $user['username']; 
... 
}

// 변경: 세션 배열 초기화 및 세션 쿠키 만료 후 파기 // logout.php 수정
$_SESSION = array(); 
if (ini_get("session.use_cookies")) { 
$params = session_get_cookie_params(); 
setcookie(session_name(), '', time() - 42000, 
$params["path"], $params["domain"], $params["secure"], $params["httponly"] 
); 
} 
session_destroy(); 
header("Location: index.php");

관점 3. 접근 제어

관리자 페이지와 게시글·댓글 삭제 요청의 권한 검증 변경 내용을 정리합니다.

3-2 | 관리자 페이지 접근 검증

로그인 여부와 관리자 권한을 함께 검증합니다.

수정 전

// 기존: 단순 로그인 여부만 검증하고 관리자 권한 미검증 // admin.php
if(!isset($_SESSION['user_id'])) {
    echo "<script>alert('로그인이 필요합니다.'); location.href='login.php';</script>";
    exit;
}
$users = mysqli_query($conn, "SELECT * FROM users ORDER BY id DESC");

수정 후

// 변경: 세션 검증 시 관리자 권한 조건 추가 // admin.php 수정
if (!isset($_SESSION['user_id']) || !isset($_SESSION['is_admin']) || $_SESSION['is_admin'] != 1) {
    echo "<script>alert('관리자만 접근할 수 있습니다.'); location.href='index.php';</script>";
    exit;
}

관점 4. 파일 업로드

업로드 파일의 확장자 검사와 저장 파일명 변경 내용을 정리합니다.

4-1 | 허용 확장자 검사

허용 확장자 목록을 기준으로 업로드 파일의 확장자를 검사합니다.

수정 전

// 기존: 파일 업로드 시 확장자 검증 로직 부재 // write.php / mypage.php

if (isset($_FILES['file']) && $_FILES['file']['error'] == UPLOAD_ERR_OK) {
    $upload_dir = 'uploads/';
    $destination = $upload_dir . basename($_FILES['file']['name']);
    move_uploaded_file($_FILES['file']['tmp_name'], $destination);
}

수정 후

// 변경: 화이트리스트 확장자 검증 추가 // write.php / mypage.php 수정

$file_name = $_FILES['file']['name'];
$file_ext = strtolower(pathinfo($file_name, PATHINFO_EXTENSION));
$allowed_exts = array('jpg', 'jpeg', 'png', 'gif', 'pdf', 'txt', 'zip');

if (!in_array($file_ext, $allowed_exts)) {
    echo "<script>alert('허용되지 않는 파일 형식입니다.'); history.back();</script>";
    exit;
}

4-2 | 저장 파일명 난수화

random_bytes()를 사용하여 저장 파일명을 난수화합니다.

수정 전

// 기존: 웹 접근이 가능한 uploads 디렉터리에 원본 파일명 그대로 저장 // write.php / mypage.php
// 난수화 또는 파일명 변경 없이 사용자 입력 파일명 그대로 저장

$destination = $upload_dir . basename($_FILES['file']['name']);

수정 후

// 변경: random_bytes()를 사용한 파일명 난수화 저장 // write.php / mypage.php 수정

$new_filename = bin2hex(random_bytes(16)) . '.' . $file_ext;
$destination = $upload_dir . $new_filename;
move_uploaded_file($_FILES['file']['tmp_name'], $destination);
